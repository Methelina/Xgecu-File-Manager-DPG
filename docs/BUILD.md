## 3. Запуск

Из существующего окружения:

```powershell
xgecu_env\Scripts\python.exe -X utf8 src\gui_dpg.py
```

Демо-режим без оборудования:

```powershell
xgecu_env\Scripts\python.exe -X utf8 src\gui_dpg.py --demo
```

Проверенный вариант использует Windows с рабочим OpenGL-драйвером. Переносимость текущего USB-слоя на Linux/macOS не реализована: используются winreg, kernel32 и winusb.

Для нового окружения можно установить основные GUI/сборочные зависимости; это инструкция воспроизведения, её выполнение в чистой системе отдельно не проверялось:

```powershell
py -3.11 -m venv ..\venv
..\venv\Scripts\python.exe -m pip install dearpygui==2.3 Pillow==13.0.0 PyInstaller==6.22.3
```

Не пересоздавайте существующее окружение без необходимости. Для проверок окна через win32gui/win32process дополнительно нужен pywin32. Доступность USB не следует из успешного импорта библиотек: T48 должен иметь подходящий WinUSB-драйвер и доступный интерфейс.

## 4. Основная сборка (DPG)

Закройте ранее запущенный EXE, затем из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File compile_bin.ps1 -InstallBuildDeps
```

Результат: `bin\T48_eMMC_dpg_v<ver>.exe`. Это один оконный файл без консоли. Внутри находятся интерпретатор и упакованные ресурсы. При запуске onefile распаковывает временные файлы; это нормальная работа PyInstaller. Первый запуск может занимать время.

Spec (`T48_eMMC_dpg.spec`) включает:

- точку входа `src\gui_dpg.py`;
- каталог `assets` и `.version.cfg` как data;
- сбор зависимостей dearpygui через `collect_all`;
- hidden import `modes.emmc.autoconfig`;
- иконку `assets/xgecu_prog.ico`;
- `name='T48_eMMC_dpg'`, `console=False`.
- исключения: `kivy`, `kivy_deps`, `numpy`, `matplotlib`.

`upx=True` в spec не означает, что UPX установлен или применился ко всем компонентам. DLL собираются механизмом PyInstaller и его hooks; не предполагайте, что один список Python-пакетов гарантирует переносимость на любую Windows.

## 5. Пути ресурсов

`gui_dpg.py` использует `_project_root()` для разрешения путей к `assets/` и `.version.cfg` как в dev-режиме (рядом с `src/`), так и в frozen-режиме (рядом с распакованными ресурсами). PNG иконки также определяется относительно модуля.

## 6. Логотип и ресурсы

| Ресурс | Назначение |
|---|---|
| `assets/logo_technical.svg` | Выбранный строгий горизонтальный логотип Xgecu Prog |
| `assets/logo_bright.svg` | Альтернативный яркий вариант |
| `assets/xgecu_prog.png` | Квадратный знак 256×256 для окна |
| `assets/xgecu_prog.ico` | Иконка EXE: 16, 24, 32, 48, 64, 128, 256 пикселей |
| `assets/fonts/` | ModeSeven, VCR OSD Mono RUS, JetBrains Mono NF, DejaVu Sans Mono |

Квадратная иконка использует знак микросхемы без длинной надписи. В `DpgGui` заданы title `Xgecu Prog v<ver>` и путь PNG; в spec — ICO. Чтобы обновить обе иконки, нужны оба ресурса и повторная сборка.

## 7. Проверка результата

После сборки проверьте запуск из `bin` или другой рабочей папки, появление окна Xgecu Prog и иконки, отсутствие диалога исключения, открытие интерфейса и штатное закрытие. Этот запуск не требует чтения или записи eMMC.

Размер EXE не закреплён как контракт и меняется с зависимостями и ресурсами.

Проверка сборки не подтверждает аппаратную совместимость с любым чипом. Программные и аппаратные проверки перечислены в [TESTING.md](TESTING.md).

## 8. Состав поставки и воспроизводимость

Для пользователя достаточно EXE, подходящего драйвера и оборудования; документацию можно хранить рядом отдельно. Текущая сборка явно не включает каталог docs. Для разработки нужны исходники и тестовые fixtures (`gpt.bin`, scatter-пример), а не только EXE.

Полного lock-файла, автоматического номера версии, подписывания кода и гарантии побитно воспроизводимой сборки здесь не настроено. Лицензирование проекта и сторонних ресурсов нужно определять по соответствующим исходным лицензиям; эта документацию новую лицензию не назначает.
